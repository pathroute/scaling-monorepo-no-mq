# Working in this repo

A small SaaS product suite built with Bazel: Go services, TypeScript web apps, Python data jobs, and shared libs that many projects depend on. Every toolchain is downloaded and pinned by Bazel. You only need `bazel` (Bazelisk); don't install Go, Node, pnpm, Python or uv yourself.

## Layout

| Path | What | Language |
|---|---|---|
| `services/<name>/` | 10 HTTP services: `api/` (wire types), `server.go` (+ tests), `cmd/<name>/main.go` (binary) | Go |
| `libs/go/{platform,authz,db,aiclient}` | Shared Go libs: config/logging/HTTP, tokens and roles, storage, LLM client | Go |
| `web/<name>/` | 4 React apps: `src/App.tsx` (+ `App.test.tsx`), `src/main.tsx`, `index.html` | TypeScript |
| `libs/ts/{ui-kit,api-client}` | Shared React components; typed client for the services | TypeScript |
| `data/{etl,models,pipelines}/<name>/` | Data jobs (polars, scikit-learn), code in `<name_with_underscores>/` | Python |
| `libs/py/common/` | Shared Python utils (`pathroute_common`) | Python |
| `tools/` | Bazel macros and helper scripts | Starlark |
| `.factory/`, `<project>/changes/` | Written by the factory. **Never edit, move or build them.** | |

Shared libs are hotspots: changing one rebuilds and re-tests everything that depends on it.

## Commands

```sh
bazel test //...                          # everything
bazel test //services/todo/...            # one project
bazel build //web/todo-web:bundle         # production bundle of one app (Vite)
bazel run //:gazelle                      # regenerate Go and Python BUILD files after changing imports
bazel query 'rdeps(//..., //libs/go/db)'  # what depends on a lib
```

## Go

- One module for the whole repo: `go.mod` (module `github.com/pathroute/suite`, Go 1.27).
- After adding, removing or changing imports, run `bazel run //:gazelle`. Never hand-edit Go BUILD files.
- Adding a third-party module: `bazel run @rules_go//go -- get example.com/mod@vX.Y.Z`, then `bazel run //:gazelle` and `bazel mod tidy`.
- Other Go tools: `bazel run @rules_go//go -- vet ./...`, `bazel run @rules_go//go -- mod tidy`.
- Service tests use `libs/go/platform/platformtest` (`Do`, `Decode`, `Expect`) and `authz.TestToken(...)`.
- A service may import another service's `api` package (as `search` does), never its server package.

## TypeScript

- BUILD files are hand-written and tiny: `ts_package(...)` for libs, `web_app(...)` for apps (`tools/ts/defs.bzl`). They compile everything under `src/` with tsc (TypeScript 7) and run `src/**/*.test.ts(x)` with Jest.
- When a file imports a new package, add it to `deps` in that package's BUILD file: `"//:node_modules/<pkg>"` for third-party packages, `":node_modules/@suite/<lib>"` for workspace libs.
- Third-party versions live only in the root `package.json` (one version of each). After editing any `package.json`, run `bazel run -- @pnpm//:pnpm --dir $PWD install --lockfile-only` and commit `pnpm-lock.yaml`.
- To use a workspace lib in an app, add `"@suite/<lib>": "workspace:*"` to the app's `package.json`, re-lock, and add `":node_modules/@suite/<lib>"` to the app's deps.
- Native ESM: relative imports end in `.js`, even from `.ts`/`.tsx` files (`import { App } from "./App.js"`).
- Tests import from `@jest/globals` (`describe`, `test`, `expect`, `jest`). jest-dom matchers (`toBeInTheDocument`, ...) are available everywhere. Use `import { userEvent } from "@testing-library/user-event"` (the named export).
- Tests run in jsdom by default. Put `/** @jest-environment node */` at the top of a test that needs Node's `fetch`/`Response` instead of a DOM.
- `jest.mock()` doesn't work in native ESM. Pass dependencies in instead (the apps take a `client` prop; tests pass a fake).
- Jest is pinned to 30.5.0: 30.5.1+ fails inside the Bazel sandbox. Don't bump it without running `bazel test //web/... //libs/ts/...`.

## Python

- uv workspace: the root `pyproject.toml` lists the members; each project has its own `pyproject.toml`.
- Adding a dependency: add it, pinned (`"name==X.Y.Z"`), to the project's `pyproject.toml`, then run:
  1. `bazel run //tools/python:requirements.update` (runs `uv lock` and regenerates `requirements_lock.txt`)
  2. `bazel run //:gazelle_python_manifest.update`
  3. `bazel run //:gazelle`
- Imports are package-absolute: `from pathroute_common import schema`, `from churn import model`. Each project directory is a Gazelle `python_root`.
- Tests are `*_test.py` files next to the code, run with pytest (`py_pytest_test`). BUILD files are generated by Gazelle; don't hand-edit them.
- Other uv commands: `bazel run @multitool//tools/uv:workspace_root -- <args>`.

## Rules

- Keep every version pinned. Bump toolchains and rulesets only in their own change.
- Hand-written BUILD globs stay inside `src/`. Never glob a whole project directory: the factory adds `changes/*.md` files there.
- Never edit lockfiles by hand (`MODULE.bazel.lock`, `go.sum`, `pnpm-lock.yaml`, `uv.lock`, `requirements_lock.txt`, `gazelle_python.yaml`). Regenerate them with the commands above.
- Before you finish, `bazel test` the projects you touched and everything that depends on them. If you changed a lib, run `bazel test //...`.
